# 05 — 建群自动流水线 + 账务卡片

**What to build:** 新建外部客户群后，系统自动跑完交付流水线并在群内落下友好账务卡片。角色：技术=花名册匹配（多名随机固化 1 人）、拉群人=建群者、老板=其余且全列、紧急联系人=全局配置。步骤顺序：角色说明 → 注意事项 → 业务三段 → 按「日期+技术标识+后缀」改群名 → 抽中技术介绍 → 友好账务卡片。步骤幂等；内部群默认不触发，全局开关可放开；零技术写「待分配」并 skip 技术向步骤。

**Blocked by:** 02 — 技术花名册 CRUD; 03 — 全局配置与收款码素材; 04 — WeComGateway + 企微回调验签解密

**Status:** ready-for-agent

- [ ] 外部客户群创建事件触发流水线；默认内部群不触发；全局开关打开后全部群可触发
- [ ] 能从成员快照识别技术（花名册 UserID）、拉群人（creator）、老板（其余且多人全列）
- [ ] 多名启用技术在群时随机只选定 1 人并持久化到该群；同一 chat 重复事件不改已固化人选
- [ ] 零技术时角色说明含「待分配」，改名/技术介绍按 skip 处理且流水线不崩溃
- [ ] 步骤按序执行：`role_announcement` → `delivery_notice` → `biz_flow_text` → `biz_feature_text` → `biz_extend_text` → `rename_group` → `tech_intro` → `account_card`
- [ ] 每步状态为 pending/done/skipped/failed；整群续跑只执行非 done/skipped
- [ ] 同一建群事件重复投递不导致重复群发（幂等）
- [ ] 内部成员尽量 @，外部老板只展示名称不强行 @；紧急联系人在群则 @，否则姓名+联系方式
- [ ] 群名格式：`{MM-DD}-{技术标识}{固定业务后缀}`（后缀来自全局配置）
- [ ] 流水线末尾发出友好账务卡片（入账/发码/结清入口形态具备，具体账务动作在 06–08）
- [ ] 中途进人事件默认忽略、不自动说话
- [ ] 主 seam 单测：假网关断言发送/改名序列与步骤状态（含双技术只介绍抽中者、二次事件无新增 Send）
